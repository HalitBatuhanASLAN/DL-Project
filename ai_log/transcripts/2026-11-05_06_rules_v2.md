# Training options for rules-v2

My recommended package is a small 4-block CNN with average pooling, GAP and BatchNorm. It uses L1 loss, AdamW with cosine decay, batch size 32 and at most 3,000 steps, with the same rule for every model.

Parameters and MACs below are measured with a size check on random weights, using no data and no training. Time, energy and "will it converge" are untested estimates. I worked from your list and `ai_log/report_notes.txt`, not the spec PDF, so check item 6 against the spec.

## 1. Own CNN

| Option | Design | Params | MACs at 128x96 | Receptive field | Trade-off |
| --- | --- | --- | --- | --- | --- |
| A | 3 blocks, 16-32-64 | 23,473 | 30.08 M | 18 px (3.1 d) | Saves only 19 % of MACs, and sees less of a dense cluster |
| **B (recommended)** | 4 blocks, 16-32-64-64 | 60,465 | 37.16 M | 38 px (6.5 d) | Good reach, and the simplest to explain |
| C | B with depthwise-separable blocks 2-4 | 8,449 | 6.48 M | 38 px (6.5 d) | 5.7× cheaper, but more to explain and less capacity. Better as the ablation (item 8) |

**Recommended design:** each block is 3x3 conv (padding 1, no bias), BatchNorm, ReLU. The first three blocks are followed by 2x2 average pooling.

| Layer | Output (C x H x W) | Params | Receptive field (px) | Jump | MACs |
| --- | --- | --- | --- | --- | --- |
| Input | 1 x 96 x 128 | 0 | 1 | 1 | 0 |
| Conv1 + BN | 16 x 96 x 128 | 144 + 32 | 3 | 1 | 1,769,472 |
| AvgPool | 16 x 48 x 64 | 0 | 4 | 2 | 0 |
| Conv2 + BN | 32 x 48 x 64 | 4,608 + 64 | 8 | 2 | 14,155,776 |
| AvgPool | 32 x 24 x 32 | 0 | 10 | 4 | 0 |
| Conv3 + BN | 64 x 24 x 32 | 18,432 + 128 | 18 | 4 | 14,155,776 |
| AvgPool | 64 x 12 x 16 | 0 | 22 | 8 | 0 |
| Conv4 + BN | 64 x 12 x 16 | 36,864 + 128 | 38 | 8 | 7,077,888 |
| GAP | 64 x 1 x 1 | 0 | whole image | n/a | 0 |
| Linear | 1 | 65 | whole image | n/a | 64 |
| **Total** | | **60,465** | | | **37,158,976** |

**Formulas for the exam:**
- Conv params = k² · in · out. BN adds 2 · out.
- Conv MACs = k² · in · out · H · W, using the output size.
- Receptive field: RF_new = RF + (k−1) · jump, and jump_new = jump · stride.
- BN and pooling count as 0 MACs here. BN also stores 2 · out non-trained buffers.

| Choice | Options | Recommendation and reason |
| --- | --- | --- |
| Pooling | Average, max, stride-2 conv | **Average.** It keeps total evidence, and max saturates when two nuclei share a window, which undercounts dense images |
| Head | GAP, flatten | **GAP.** Flatten adds 11,521 params, depends on position, and wouldn't run at 256x192 without changing the head |
| Normalisation | BatchNorm, GroupNorm/InstanceNorm, none | **BatchNorm.** It subtracts a batch mean, so brightness differences between images survive. Per-image norms would delete the brightness signal |
| Residual blocks | Yes, no | **No.** Four layers have no vanishing-gradient problem |

**Link to nucleus size (d = 5.8 px):**
- Conv1 sees about half a nucleus, conv2 about 1.4 d, conv3 about 3.1 d and conv4 about 6.5 d.
- So the network sees single nuclei, touching pairs, then local crowding.

**Link to brightness:**
- A filter passing intensity, then average pooling, then a linear layer, is almost exactly the OLS model. The CNN can learn the shortcut easily.
- What it can add is what the mean ignores:
  - overlaps
  - nuclei that are dimmer or brighter than usual
  - nuclei cut by the border
  - blur effects
- Some of the 1.08 cells may be noise that no model can remove. A CNN not winning would be a valid result.

## 2. Loss (target = count/100)

| Option | For | Against |
| --- | --- | --- |
| **L1 (recommended)** | Matches the MAE metric, no extra hyperparameter | Constant gradient, so it needs LR decay (cosine provides this) |
| MSE | Smooth | An error of 1 cell is 0.0001 on this scale, it weights large errors, and it optimises RMSE rather than MAE |
| Huber | Smooth near zero | Needs a δ on the 0-1 scale, and there are few outliers to justify it |

## 3. Optimizer

| Item | Options | Recommendation |
| --- | --- | --- |
| Optimizer | AdamW, Adam, SGD with momentum | **AdamW.** It needs the least per-model tuning, while SGD is LR-sensitive and would need a bigger search |
| LR | Single value or per model | **Per model**, from item 5 |
| Schedule | Cosine, constant, reduce on plateau | **Cosine to 0** over the budget, no warm-up. Plateau reduction suits early stopping better but adds 2-3 settings |
| Weight decay | 0, 1e-4, 1e-2 | **1e-4** on all parameters, with no exceptions so it's easy to explain |
| Batch size | 16, 32, 64 | **32**, with `drop_last`. That gives 37 steps per epoch and steadier BN than 16 |
| Output bias | Default, train mean | **0.5005 for every model.** It skips the early steps spent learning the mean |

## 4. Budget and early stopping

**Budget:** use fixed steps. With identical data and batch size, steps and epochs are the same thing, but steps state the compute directly.

| Option | Max steps | Earliest stop | Trade-off |
| --- | --- | --- | --- |
| Small | 1,500 | 750 | Cheapest, but the scratch CNN may underfit |
| **Medium (recommended)** | 3,000 (about 80 epochs) | 1,500 | Good balance, though not yet tested |
| Large | 6,000 | 3,000 | Safest, but doubles the footprint |

**Same rule for all models:**
- Evaluate val MAE every 150 steps.
- Count an improvement only if it is at least 0.02 cells.
- Allow patience of 6 evaluations (900 steps).
- Allow no stop before step 1,500, and keep the best checkpoint.

**Caveat:** under cosine decay the error tends to keep improving until the end, so early stopping may rarely fire. If it saves little, report that as the result.

| Wider grid | 6 LRs × 3 models × 300 steps | 5,400 steps | Unlikely to change the choice |

Measured with 1-channel input and 1 output:

| Option at 128x96 | MACs | Trade-off |
| --- | --- | --- |
| **Stock networks, same input (recommended)** | As above | Honest same-input policy, but aggressive downsampling: stride 4 leaves nuclei about 1.5 px wide |

  Reason: It is small and simple, I can compute every layer by hand, and it can see a group
  of about 6 nuclei at once.
- Seeds: own CNN and MobileNetV3-Small with 3 seeds (42, 43, 44) on val; ResNet-18 with 1 seed (42).
  Seed 42 is the final model for each test run, fixed now.
  Reason: Repeating the small models is cheap, but ResNet-18 is about 11 times more expensive

- Budget: max 3,000 steps with the early-stopping rule below.
  Reason: 1,500 steps may be too short for a model trained from scratch, and early stopping
  will stop it sooner if it stops improving.

  test_seen lies entirely below 1; the energy ratio is reported next to it.
  Reason: The test set has only 100 scenes, so a small difference can be just noise; I only
  call it a win if the whole interval is below 1.
- The acceptance rule of section 8 stays as the course defines it. Every model is also compared
  with the brightness baseline (error and energy).

### 11.1 Models
- Own CNN, input 1 x 96 x 128. Block = 3x3 conv (padding 1, no bias), BatchNorm, ReLU.
  Blocks 16-32-64-64, 2x2 average pooling after blocks 1-3, GAP, linear to 1 output.
  60,465 parameters, 37,158,976 MACs, receptive field 38 px at the last conv.
- Standard models: ResNet-18 and MobileNetV3-Small, ImageNet weights (IMAGENET1K_V1), stock
  architecture, same input and normalisation as the own CNN.
  Conv1 weights summed over RGB (section 6). Last linear layer replaced by 1 output.
  MobileNet classifier dropout set to 0. All layers trained with one LR; BatchNorm in train mode.
- Every model: output bias starts at 0.5005. New layers use the PyTorch default initialisation.
- ImageNet weights: one-time download inside tracked_run, recorded in the README with file hashes.
  Their pre-training footprint is discussed qualitatively in the report.

### 11.2 Training (identical for every model)
- Loss L1 on count / 100. AdamW, weight decay 1e-4 on all parameters.
- Cosine LR from the chosen value to 0 over 3,000 steps, no warm-up.
- Batch size 32, drop_last. Data held as tensors on the GPU, no workers.
- Mixed precision off, except the one measured run in 11.5.
- cudnn.deterministic = True, cudnn.benchmark = False. Python, NumPy, torch and CUDA seeds all fixed.

### 11.3 Early stopping (identical for every model)
- Evaluate val MAE in cells, in eval mode, every 150 steps.
- Improvement = val MAE ≤ best − 0.02 cells. An improvement saves the checkpoint and resets
  the counter; anything else adds 1 to the counter.
- Stop at the first evaluation with step ≥ 1,500 and counter ≥ 6, otherwise at step 3,000.
- The saved checkpoint is the model. Evaluations count as part of the run.

### 11.4 LR search
- Grid 1e-4, 3e-4, 1e-3, 3e-3, 300 steps each, full train set, seed 42, cosine over 300 steps.
- Each trial is its own tracked run, category "search".
- Choice: lowest val MAE at step 300; a tie goes to the lower LR.
- If the best LR is on the edge of the grid, one more value beyond it (× 3 or ÷ 3, rounded to the
  same 1-3 pattern), for any model. Same choice rule.
- Ablations and the mixed-precision run reuse the LR of their parent model.

### 11.5 Ablations and efficiency runs (val only, seed 42, own CNN unless stated)
- Resolution: same network at 256x192.
- Depthwise-separable: blocks 2-4 become 3x3 depthwise, BN, ReLU, 1x1, BN, ReLU.
  8,449 parameters, 6,475,840 MACs.
- Mixed precision: ResNet-18, seed 42, same LR.
- Reported without extra training: caching and early stopping.
- Quantization, pruning and distillation are not used.

### 11.6 Failed runs [filled in]
- A crash from a technical cause may be repeated with the same seed; both runs stay in the index.
- A model that trains badly is not replaced. Seed 42 stays the final model, and the budget stays
  3,000 steps.

### 11.7 Measurement
- MACs: `torch.utils.flop_counter.FlopCounterMode`, 2 flops = 1 MAC. BN and pooling count as 0.
- Latency: eval mode, no_grad, batch size 1, on GPU and CPU, on val images. 200 warm-up passes,
  then 5 repeats of 1,000 timed passes; median and p95. torch.cuda.synchronize() before each
  GPU timer read. CPU thread count fixed.
- Energy per 1,000 predictions: on val images, category "measure", loop of at least 60 s, 3 repeats,
  after a 60 s idle measurement. Gross and net of idle are both reported.

### 11.8 Reporting
- Footprint three ways: final training run (seed 42); training incl. LR search (seed 42 plus that
  model's trials); project total (`runs/index.csv`, all seeds, ablations and failed runs).
- Each CNN's ratio to brightness is reported separately, with its CI. test_unseen ratios are a
  diagnostic only.
- Residuals by count are reported for every model: from the test predictions for final models
  and from val predictions for ablations.
- Val spread over seeds is reported for the own CNN and MobileNetV3-Small. ResNet-18 has none.

## What is inconsistent or risky

### Needs fixing before the freeze

1. **The "2 untracked runs" count is wrong.** I also ran two small Python commands last session: one summed `runs/index.csv` and one did a division. The 2 s for the size check was my estimate, not a timing, and I can't speak for earlier sessions. The draft's definition of a run excludes reading logs, so the index sum needs no row, but the division is a judgement call.
   - Suggested fix: keep the definition, and add rows only for the self-test and the size check.
   - Those rows have no energy data, so the project total stays slightly low. The self-test's duration was measured at 1.15 s.

2. **Your section 9 wording doesn't match what the script did.** "Only for format checks" isn't true, because `build_cache.py` also resized the test images and wrote them to the cache. The draft says this directly. It also discloses that the exception came after the run.

3. **The reason in 1A is inaccurate and could cost you in the exam.** 38 px is about 6.5 nucleus diameters across, not 6 nuclei. That area can hold far more than 6 nuclei at high counts, and the 38 px is only the theoretical limit. Your reason is verbatim in the draft as you asked. I suggest replacing it with: "it can see about 6.5 nucleus diameters across".

4. **The energy ratio in 4A isn't defined yet, and brightness may break it.** Brightness inference is so cheap that its energy, net of idle, may be lost in measurement noise. A ratio could then be huge or even negative, and its fit was also below measurement resolution.
   - Suggested fix: use gross energy per 1,000 predictions, on CPU for both models.
   - For training energy, report absolute values, with no ratio.

### Worth accepting knowingly

5. **Early stopping may do less than your reason in 3B suggests.** It can't stop before step 1,500, and with cosine decay the error usually keeps improving late. If it does stop early, for example at step 2,000, the LR is still about 25 % of its start, so the model misses its best low-LR phase.

6. **The mixed-precision run has no noise yardstick.** ResNet-18 runs only once without mixed precision, so a single energy difference can't be separated from run-to-run variation. Compare energy per step, and treat any error change as tentative. A 600-step repeat of the plain run would give a rough noise estimate, at low cost.

7. **"11 times more expensive" is a MACs figure.** Real GPU energy per step won't scale exactly with MACs, so measure it. ResNet-18 is also about 31× MobileNet's MACs, and it has no seed spread at all, so you can't say whether its result is typical.

8. **Footprint has an interpretation you should confirm.** I read "training incl. LR search" as seed 42 plus that model's trials. Otherwise MobileNet would look 3× worse than ResNet-18 purely because of extra seeds. Seeds 43 and 44 appear only in the project total.

9. **Three CNNs are each compared with brightness.** With 3 comparisons and no correction, one could win by chance. The draft reports each one separately, which is fine, but the report should state this.

10. **Residuals have one gap.** Brightness and mean have no val predictions saved. Their residuals will come from the test run only, so the val and test views differ between baselines and CNNs. If you want val residuals too, `baselines.py` needs one more tracked run.

11. **Choosing LR from 300 steps favours fast starters.** That can mean pretrained models and higher LRs, and a 3,000-step run might prefer a lower LR. This is accepted for cost reasons, and the report should state it.

12. **A 1-seed ablation can only be judged against the parent's spread.** A difference smaller than the spread across the 3 own-CNN seeds should be called "no clear difference".

### Footprint limit
Maximum planned training is 33,600 steps: 3,600 for the LR search, 21,000 for 7 final runs, and 9,000 for 3 extra runs. An edge rule adds at most 300 steps per model.
