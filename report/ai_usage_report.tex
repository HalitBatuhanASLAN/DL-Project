\section{Cases where the AI was wrong, incomplete or misleading}
The journal records 26 such cases; these six had the largest effect. None of them is invented: each is visible
in the linked chats, session logs or git history.

\textbf{Case 1 --- Missed data leakage (Claude, project chat).} The first recommendation of BBBC005 proposed
selecting some blur levels but did not mention that the 19{,}200 files are only 600 scenes rendered 32 times.
\emph{Detected} by asking a second Claude chat and ChatGPT, both of which raised it. \emph{Fixed} by a
scene-grouped split, verified by four built-in checks (no scene in two splits, balanced cells). This is the
same subject-exclusive split as in the gait paper I presented in class (Zhao et al.\ 2024). \emph{If missed:}
the same layouts in train and test (pixel correlation 0.89), so an optimistic test error.

\textbf{Case 2 --- Stain identity: a guess, then the documentation, both wrong in different ways.} A Claude
Desktop chat first said ``w1 is very likely the nuclei'' from the mean brightness of five images. I pointed to the
official page (``2 = nuclei''), and it switched to w2. Our own frozen pixel test then showed that the w1 object
lies fully inside the w2 object and is 3--4$\times$ smaller: w1 \emph{is} the nuclei channel. \emph{Lesson:}
neither a weak heuristic nor the documentation replaced a direct measurement; the conflict is reported.

\textbf{Case 3 --- A decision rule that measured the wrong thing (rule proposed by AI, approved by me).} The
resolution check found ``peaks'' with 1\,px smoothing, while a nucleus is 31.7\,px wide. It counted texture
inside nuclei (154--185 peaks in images with 100 nuclei) and rejected every resolution, which would have forced
$348\times260$, about 7.4 times the pixels per step. \emph{Detected} by the coding agent's diagnostic plot, which it
showed me instead of changing the rule silently. \emph{Fixed} by one principle (peaks at nucleus scale), with all
thresholds unchanged; the revision is tagged and disclosed as not pre-registered. Two of the three changes I wrote
had no effect (they rounded to the old values), which the agent also pointed out.

\textbf{Case 4 --- Gemini suggested inventing ``AI errors'' for this report.} It listed three ready-made examples
(e.g.\ ``the AI forgot the stride in the receptive field''). None of them happened. \emph{Rejected:} writing them
would be fabrication. In the same answer, it claimed that an own-CNN MAE of 6--7 would ``pass without hesitation'',
then itself computed the limit as $1.15\times4.5=5.17$. \emph{Detected} by doing the arithmetic.

\textbf{Case 5 --- A misleading energy comparison (Claude, project chat).} We first reported that $256\times192$
needs ``4$\times$ the MACs but only 2$\times$ the energy'' and the depthwise variant ``0.66$\times$ the energy''.
These compared \emph{whole runs} that early stopping had ended at different steps. \emph{Detected} while drafting
the report, by recomputing energy per step: $2.98\times$ and $0.90\times$. \emph{Fixed} in the report and in
\texttt{summary.md}; the corrected numbers make the ``MACs do not predict energy'' point stronger.

\textbf{Case 6 --- Smaller but real coding-agent errors.} (a) A BatchNorm diagnostic fed scene-sorted batches
and produced absurd errors (120 cells); the agent noticed the implausible result, fixed the shuffle and re-ran;
both runs stay in the index. (b) Twice an edit command silently changed nothing; caught by \texttt{git status}.
(c) A first install command from the project chat gave a CPU-only PyTorch; caught from the wheel size and
\texttt{cuda.is\_available()=False} --- otherwise every ``GPU'' energy number would have been a CPU number.
(d) While searching my computer for transcripts, the agent read file names from unrelated projects; it noticed
this itself before committing, and I decided to publish only masked transcripts and made the repository private.

\section{How I verified AI-generated code and claims}
\begin{itemize}
\item \textbf{Hand calculations.} Every layer of \kn{} (output shape, parameters, receptive field, MACs) by the
course formulas; the analytic mean-baseline MAE ($517/20=25.85$); the acceptance limit ($1.15\times1.249=1.436$).
\item \textbf{Built-in checks in every script:} split (4 checks), cache (41 checks), layer table (25 checks:
hand formula $=$ \texttt{sum(p.numel())} $=$ \texttt{FlopCounterMode}), init check (every model starts at MAE 25.85),
reproducibility (two runs bit-identical), pre-test checks (shuffling, artifact hashes, no earlier test use).
\item \textbf{Comparison with documentation and with the data.} Dataset page vs.\ pixel test (Case 2); PyTorch
install selector vs.\ driver limits; course slides for the receptive-field formula.
\item \textbf{Cross-checking between models.} The same question to Gemini, ChatGPT and two Claude chats (Case 1).
\item \textbf{Freezing before looking.} Rules were committed and tagged before the runs they govern, scripts were
committed before they ran, and the test script refuses a second run per model. This makes it impossible for me
or the AI to tune on the test set without leaving a trace.
\item \textbf{Plausibility checks.} Absurd numbers (Case 6a), impossible counts (``C50'' is not a count level),
arithmetic that did not add up (Cases 4 and 5) and step counts were questioned before anything was accepted.
\end{itemize}
